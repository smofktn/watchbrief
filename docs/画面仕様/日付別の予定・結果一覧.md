# 日付別の予定・結果一覧（Issue #88）

`/reports` 内の「日付別の予定・結果」リンクから保護URL `/reports/daily` を開く。主要ナビは増やさない。新URLをRouterと安全なログイン戻り先allowlistへ追加し、未認証からログイン後に同URLへ戻す。

[Job一覧API](../API仕様/get-api-generation-jobs.md)の初期30件を予定時刻の新しい順に取得し、明示的なAsia/Tokyoで日付見出しと時刻を表示する。端末timezoneに依存させず、全取得行をまとめて同日のページ跨ぎで見出しを重複させない。Jobのない日を作らない。

待機中/実行中/成功/失敗を日本語で表示し、成功行だけ既存 `/reports/{report_id}` へのリンク。非成功はリンクなし。技術的な失敗理由は表示しない。「更新」は初期30件から再取得し現在状態を読む。自動polling/生成操作は追加しない。

初回読込/更新中は旧データを消去。空は「保存済みの予定・結果はありません。」。初回失敗は固定案内と再試行。続きは「もっと読む」、取得中は二重操作を抑止する。続き失敗/15秒timeout/不正200/重複ID/逆順/不整合/cursor循環では既表示とcursorを維持し、同じ続きから手動再試行。終了を表示する。

共通useResource/共有sessionを使い、認証epoch/401/route/logout/更新開始で一覧・追加状態・cursorを消し、古い応答を破棄する。cursorはメモリのみ、URL/storageへ保存せずFrontendで解読/再生成しない。順序比較はUTCマイクロ秒を保持し、Dateのミリ秒丸めを使わない。既存成功Report一覧・詳細/Markdownは維持する。
