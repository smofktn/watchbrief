## 文書の責務

- 利用者向けの振る舞い・業務ルールの正本は[プロダクト仕様](../product-definition.md)。このディレクトリでは、画面単位の構成と具体的な操作・表示を管理する。
- リクエスト・レスポンス・HTTPステータス・エラーコードは[API仕様](../API仕様/README.md)で管理し、画面仕様から参照する。
- 通信・認証の処理順と責務は[システム設計](../system-design.md#issue-53の基本設計)で管理する。Cookie・CSRF等の規則を画面仕様へ複製しない。
- **合意済み**、**提案**、**未決定**を項目ごとに区別する。設計の合意は実装・動作確認済みを意味しない。仮の表示確認用画面も完成した仕様の実装と区別する。

## 更新・確認方法

画面の追加・変更時は、対象画面の仕様書を実装と同じ変更で更新する。APIとの対応、入力条件、正常時・失敗時の表示、キーボード操作、画面幅による崩れを確認する。API契約を変える場合は対応するAPI仕様も更新し、業務ルールに影響する場合はプロダクト仕様と関連設計へ反映する。

仕様書には現在の仕様・提案・未決定事項・確認観点を残す。判断理由と実行した検証結果、未確認の範囲はIssue・PRへ記録し、合意していない案や動作を確認していない項目を完了扱いにしない。
