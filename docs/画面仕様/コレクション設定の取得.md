# コレクション設定の取得（Issue #56）

#17の順次実装の委任に基づく実装判断として、`/collections` を本人の設定一覧、`/collections/{ULID}` を読み取り専用の詳細とする。既存の `/me` からリンクで移動する。本体の新規保存は[新規作成](コレクションの新規作成.md)へ接続する。既存設定の編集・削除・並べ替えは#18の後続範囲へ残す。

## 表示と操作

- 一覧は自分のCollection名とON/OFFを保存順（display_order、同値ではID）で表示し、名前から詳細へ進む。0件は「コレクションはありません。」。
- 詳細は名前・ON/OFF・調査方針・初回確認期間の方針・日本時間のcron式・対象・情報源を表示する。空の任意指示、Scheduleなし、対象なし、情報源なしを区別する。
- 情報源URLは文字列として表示する。HTML挿入・外部URL取得は行わない。
- 取得中は読込表示、失敗時は以前の設定を消して固定のエラー文と「設定を再試行」を表示する。404は他Userと不存在を区別せず「見つかりません。」。
- APIの成功JSONも型・正規ID・配下配列・lookback条件を確認してから表示する。不正な成功応答で画面を壊したり、APIの任意messageをそのまま表示したりしない。

## 認証・遷移・個人データ

[保護URLとログイン復帰](保護URLとログイン復帰.md)の許可一覧に、一覧と正規ULIDの詳細だけを追加する。未認証なら同じパスを戻り先としてログインへ送り、成功後の本人確認が通ってから設定を読む。クエリ・フラグメント・外部URLは戻り先に使わない。

ルート移動・再読込・本人情報確認開始時に以前の設定を消す。設定APIの401では本人情報と設定を消し、ログインへ移る。500/通信失敗では保護URLを維持して再試行する。

ログアウト開始時には本人情報と設定を同期的に消す。遅い本人情報・設定応答は要求世代を照合して無視し、logout-error中の履歴移動でも再取得しない。ログアウト完了未確認時は設定取得ではなく、従来のログアウトだけを再試行する。トークン・設定をlocalStorage/sessionStorageへ保存しない。

対応APIは[設定取得API](../API仕様/get-api-collections.md)。認証・Cookie・CSRF契約は[共通API仕様](../API仕様/README.md)に従う。実行した検証結果と未確認の範囲はIssue/PRへ記録する。
