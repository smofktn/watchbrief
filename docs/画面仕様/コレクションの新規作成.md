# コレクションの新規作成（Issue #18）

## 採用状況と経路

Collection本体から新規保存する範囲と、同じ要求の再試行で重複作成しない方式に合意した。URL・ラベル・要求番号・入力上限と具体表示は、その合意を具体化する実装判断である。

一覧の「新規作成」から `/collections/new` を開く。未認証ならログイン後に同じパスへ戻る。新規画面は空の編集フォームで、保存成功後は `/collections/{ULID}` の既存詳細表示へ移る。一覧へ戻った後や再読み込みでも保存値を取得する。

## 入力と操作

| 入力 | 表示と条件 |
|---|---|
| 名前（必須） | 1〜200文字、空白だけは不可 |
| 調査方針（任意） | 改行できるテキスト欄、10,000文字以内 |
| 初回の更新確認期間 | 初期値は「AIにおまかせ」。「日数を指定」なら1〜365日の整数欄を表示 |

状態は停止中と表示する。ONに必要なWatchTargetとScheduleがないことを説明し、今回のフォームには有効化や配下設定の入力を追加しない。これらは#18の後続範囲である。保存データの厳密な条件は[作成API](../API仕様/post-api-collections.md)を参照する。

保存前の下書きは画面メモリに保持し、入力条件を画面とAPIの両方で検証する。「保存」を押すと送信中はフォームと保存ボタンを無効化し、重複送信を止める。入力不正は欄の近くへ表示し、最初の不正欄へフォーカスする。「一覧へ戻る」で移動できる。未保存変更の確認ダイアログは#42へ維持する。

## 保存の状態

| 状態 | 表示・操作 |
|---|---|
| 保存中 | 「保存結果を確認しています。」と入力・保存操作の無効化 |
| 成功 | APIの正規IDを検証して詳細へ移動。詳細取得失敗時は既存の取得再試行を使い、作成POSTを再発行しない |
| 最初の400 | 入力保持、固定の条件案内、修正・再保存が可能 |
| 最初の403 | 入力保持、送信元を確認できない固定案内 |
| 通信失敗・timeout・500・不正な成功応答 | 保存結果不明と表示。入力を保持して編集を止め、「同じ内容で再試行」 |
| 409 | 一覧で保存結果を確認する案内。同じ要求を再送するボタンは無効 |
| 401 | 個人データを消去し、新規画面を安全な戻り先としてログインへ |

結果不明後の再試行では、同じ要求番号と本文を送る。再試行が400/403でも最初の保存が成功していた可能性が残るため、本文・番号を保持する。番号を失う画面離脱・再読み込み後は一覧で確認する。自動再送や名前による重複判断は行わない。

## 認証・消去・画面幅

単一sessionを共有し、ログアウト開始、画面移動、本人確認開始時に下書きを消去する。遅い保存応答は世代・session・現在URLを照合して捨て、別画面への遷移や個人データの復活を起こさない。要求をabortしても認証通過後のサーバー保存まで取り消す保証はない。トークン・入力・要求番号を永続ストレージやURLへ入れない。

ラベル・補助文・入力エラーを関連付け、キーボードで入力・保存・一覧へ戻る操作ができるようにする。PCとスマホで入力欄が画面幅へ収まり、長い保存値も折り返して読めるようにする。実ブラウザ、実DBとテスト内の応答注入は区別してIssue・PRへ記録する。
