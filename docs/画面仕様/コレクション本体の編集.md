# コレクション本体・対象・情報源・Scheduleの編集（Issue #74・#78・#80・#82）

## 合意と経路

競合時に下書きを残して保存を止める方針と、版番号＋更新要求番号で安全に再試行する方式に合意した。URL・操作ラベル等はその合意を具体化する実装判断である。[プロダクト仕様](../product-definition.md#collection本体の編集issue-74)を正本とする。

停止中Collectionの詳細 `/collections/{ULID}` の「編集」で同じURL内の編集モードへ切り替える。取得済みの名前・任意方針・初回期間と版を引き継ぐ。ONのCollectionには編集ボタンを表示せず、APIでも停止中か確認する。配下設定の表示・編集方法を将来も分離する決定ではない。

名前1〜200文字、任意方針0〜10,000文字、初回AI又は1〜365日は[更新API](../API仕様/patch-api-collections.md)に従う。新規作成と共通の入力部品・検証を使い、改行・空白を保持する。保存前に不正欄へ案内し、最初の不正欄へフォーカスする。版や要求番号を利用者の入力欄にしない。

## 操作と状態

| 状態 | 操作・表示 |
|---|---|
| 編集可能 | 「保存」「詳細へ戻る」。本体と変更した対象・情報源・Scheduleをまとめて保存 |
| 保存中 | 入力と保存を無効化し、結果確認中と表示。重複要求を出さない |
| 200 | 編集を終えて詳細を再取得。現在値を表示し、一覧・再読み込みも既存GETを使う。GET失敗時は取得だけ再試行 |
| 最初の400/403 | 下書きを保持し、固定の入力条件/送信元案内。保存結果不明の再試行後なら編集ロック・元要求を維持 |
| 通信断・timeout・500・不正な成功応答 | 保存結果不明。下書き・要求番号・本文を保持して入力を無効化、「同じ内容で再試行」 |
| 409 update_conflict / collection_not_stopped | 下書きを保持して保存を止め、「最新値を確認」へ |
| 409 update_request_conflict / 404 | 保存を止め、詳細へ戻って確認する案内 |
| 401 | 個人データと下書きを消去し、同じ詳細URLを戻り先としてログインへ |

成功応答のIDと版の形式も検査する。APIの任意messageをそのまま表示しない。自動再送はしない。

## 競合後の編集し直し

タブAが名前を保存した後、古い名前を持つタブBが調査方針を保存しても、タブAの名前を上書きしない。タブBの下書きを残して保存を止める。「最新値を確認」でGETし、下書きの下に最新の保存値を表示する。取得失敗でも下書きを残し、最新値の取得を再試行できる。

最新値が停止中なら「最新値で編集し直す」を表示する。ボタンの前に、下書きと見比べ、この操作で入力欄を最新値へ置き換えることを説明する。利用者が押した後に最新値と版を引き継いで編集を再開し、必要な変更を再入力する。自動統合や古い入力の自動再送を行わない。その後の再競合も同じ手順とする。最新値がONなら編集再開を許可しない。

## 認証・離脱・確認観点

既存の単一sessionを使い、ログアウト開始・認証確認・ルート移動・編集終了で入力・要求番号を消去し、未完了要求をabortする。遅延応答は要求世代・session・現在URLを照合して破棄する。abortでサーバー保存まで取り消せるとは扱わない。入力・要求番号をURLやlocalStorage/sessionStorageへ保存しない。

「詳細へ戻る」や再読み込み後は現在値を取得する。未保存変更の確認ダイアログは#42へ維持し、今回追加しない。PC/スマホ相当幅、ラベル・エラー関連付け、キーボードとフォーカス、競合後の比較、応答喪失・実DB障害・認証失効・遅延応答・履歴不変を検証する。実試験と応答注入の結果・制限はIssue/PRへ記録する。

## WatchTarget追加・編集への拡張（Issue #78）

本節は#74の本体編集へ追加した#78の仕様である。既存詳細の編集モードで本体と対象名・任意の補足指示を扱い、最後の「保存」でまとめて確定する。対象ごとの保存ボタンは設けない。保存失敗時は全体の入力を保持し、一部だけ保存しない。新規対象はONで追加し、既存対象のON/OFFは維持する。Collectionは停止中のままとし、情報源・対象のON/OFF操作・削除・並べ替えは今回扱わない。

競合後は本体と対象の下書きを保持し、最新の本体・対象を別途表示する。「最新値で編集し直す」で全体を最新値へ置き換え、新規下書きも破棄することを操作前に説明する。API・再試行の詳細は[更新APIの拡張設計](../API仕様/patch-api-collections.md#watchtarget追加編集への拡張issue-78)を参照する。

具体操作：本体入力の下に対象一覧を並べ、各対象の対象名・補足指示を編集できるようにする。「対象を追加」で空の新規行を1つ追加する。新規行の「追加を取り消す」は未保存の行だけを除き、DBを操作しない。保存済み対象は削除できない。変更済み／新規の行だけをAPIへ送り、保存後は詳細GETで再表示する。送信待ち・結果不明中は本体と対象の編集を止め、全体の本文と要求番号を保持する。1回の保存に20行を超える変更がある場合の案内を出し、登録総数を20件に制限する意味にはしない。

## 情報源追加・編集（Issue #18）

代理判断により既存対象の入力の下へ情報源の表示名・URL・補足指示を置き、「情報源を追加」で空の行を追加する。新規下書きのみ取り消せる。保存済み情報源の削除は追加しない。新規対象では「対象を保存してから情報源を追加してください」と案内する。1回の保存は情報源20変更行、対象20変更行、本文合計1MiB。表示名200・URL2,048・補足10,000文字の条件と、HTTP/HTTPS・認証情報を含めないURLを案内する。

最後の保存で本体・対象・情報源を一括確定する。情報源の変更だけでも保存可能。最初の不正欄へフォーカスし、保存中/結果不明/競合では全体を無効化して入力・本文・番号を保持する。競合後は最新情報源もテキストで比較表示し、編集し直しで全下書きを置換することを説明する。認証変化・離脱・取消時は情報源も消去し、遅い応答を破棄する。

詳細/競合比較の名前・URL・指示はVueのテキスト補間で表示する。リンク、iframe、画像src、v-html等へ挿入せず、URLへアクセスしない。既存の古い設定も再表示時に正規化・自動書換えしない。URLの安全な取得は#20へ維持する。[Vueのセキュリティ方針](https://vuejs.org/guide/best-practices/security.html)も参照。

情報源の入力検証は新規/変更行へ適用する。未変更の旧保存値は新条件で保存を妨げず、再送もしない。情報源の表示名・URL・補足指示のうち最初の不正欄へフォーカスする。

## Schedule追加・編集（Issue #82）

利用者から委任された上ペインの代理判断により、既存の編集モードに「生成スケジュール（日本時間）」のcron式入力を追加する。`0 7 * * *` は毎日7時、`0 7,19 * * *` は毎日7時と19時の例を表示する。構文の条件は[更新APIのSchedule契約](../API仕様/patch-api-collections.md#schedule追加編集)を参照する。構文不正は欄に表示してフォーカスし、全体の下書きを保持する。未設定の空欄なら追加せず、既存Scheduleを空にした場合はエラーにする。削除は別作業。

本体・対象・情報源と最後に保存する。Scheduleだけの変更も同じ全体版で保存する。Collectionは停止中のまま、生成・実行・外部通信は開始しない。既存の結果不明時の正確な再試行、認証変化/離脱時の消去と遅い応答の破棄をScheduleへも適用する。競合後は下書きと最新の式をテキストで比較し、「最新値で編集し直す」で全体を置き換える。次回予定表示は#34へ残す。
