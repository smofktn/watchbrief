# コレクション本体の編集（Issue #74）

## 合意と経路

競合時に下書きを残して保存を止める方針と、版番号＋更新要求番号で安全に再試行する方式に合意した。URL・操作ラベル等はその合意を具体化する実装判断である。[プロダクト仕様](../product-definition.md#collection本体の編集issue-74)を正本とする。

停止中Collectionの詳細 `/collections/{ULID}` の「編集」で同じURL内の編集モードへ切り替える。取得済みの名前・任意方針・初回期間と版を引き継ぐ。ONのCollectionには編集ボタンを表示せず、APIでも停止中か確認する。配下設定の表示・編集方法を将来も分離する決定ではない。

名前1〜200文字、任意方針0〜10,000文字、初回AI又は1〜365日は[更新API](../API仕様/patch-api-collections.md)に従う。新規作成と共通の入力部品・検証を使い、改行・空白を保持する。保存前に不正欄へ案内し、最初の不正欄へフォーカスする。版や要求番号を利用者の入力欄にしない。

## 操作と状態

| 状態 | 操作・表示 |
|---|---|
| 編集可能 | 「保存」「詳細へ戻る」。保存は本体3項目だけに限定 |
| 保存中 | 入力と保存を無効化し、結果確認中と表示。重複要求を出さない |
| 200 | 編集を終えて詳細を再取得。現在値を表示し、一覧・再読み込みも既存GETを使う。GET失敗時は取得だけ再試行 |
| 最初の400/403 | 下書きを保持し、固定の入力条件/送信元案内。保存結果不明の再試行後なら編集ロック・元要求を維持 |
| 通信断・timeout・500・不正な成功応答 | 保存結果不明。下書き・要求番号・本文を保持して入力を無効化、「同じ内容で再試行」 |
| 409 update_conflict / collection_not_stopped | 下書きを保持して保存を止め、「最新値を確認」へ |
| 409 update_request_conflict / 404 | 保存を止め、詳細へ戻って確認する案内 |
| 401 | 個人データと下書きを消去し、同じ詳細URLを戻り先としてログインへ |

成功応答のIDと版の形式も検査する。APIの任意messageをそのまま表示しない。自動再送はしない。

## 競合後の編集し直し

タブAが名前を保存した後、古い名前を持つタブBが調査方針を保存しても、タブAの名前を上書きしない。タブBの下書きを残して保存を止める。「最新値を確認」でGETし、下書きの下に最新の保存値を表示する。取得失敗でも下書きを残し、最新値の取得を再試行できる。

最新値が停止中なら「最新値で編集し直す」を表示する。ボタンの前に、下書きと見比べ、この操作で入力欄を最新値へ置き換えることを説明する。利用者が押した後に最新値と版を引き継いで編集を再開し、必要な変更を再入力する。自動統合や古い入力の自動再送を行わない。その後の再競合も同じ手順とする。最新値がONなら編集再開を許可しない。

## 認証・離脱・確認観点

既存の単一sessionを使い、ログアウト開始・認証確認・ルート移動・編集終了で入力・要求番号を消去し、未完了要求をabortする。遅延応答は要求世代・session・現在URLを照合して破棄する。abortでサーバー保存まで取り消せるとは扱わない。入力・要求番号をURLやlocalStorage/sessionStorageへ保存しない。

「詳細へ戻る」や再読み込み後は現在値を取得する。未保存変更の確認ダイアログは#42へ維持し、今回追加しない。PC/スマホ相当幅、ラベル・エラー関連付け、キーボードとフォーカス、競合後の比較、応答喪失・実DB障害・認証失効・遅延応答・履歴不変を検証する。実試験と応答注入の結果・制限はIssue/PRへ記録する。
