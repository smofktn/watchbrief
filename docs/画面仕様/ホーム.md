# ホーム — Collection別の最新保存済みReportと本日状態（Issue #92・#94）

## 目的と範囲

認証済みUserが現在のCollectionから最新の保存済み成功Reportを開く最初のホーム経路。業務上の範囲は[プロダクト仕様](../product-definition.md#ホームの最初の経路issue-92)、通信は[GET /api/home](../API仕様/get-api-home.md)に従う。

この画面は現在Collection一覧と最新Reportへのリンクを主導線として表示し、本日保存済みJobの状態件数を補助情報として表示する。Collection表示順変更は後述のホーム内編集操作で行う。次回予定、生成、外部取得、ScheduleからのJob復元は扱わない。

## URLとナビゲーション

保護URLは `/home`。3つの主要ナビの最初のリンクを「ホーム」へ接続する。既存の `/me` は本人情報を確認できる保護URLとして維持し、`/` の遷移先とログイン後の既定先も `/me` のままとする。未認証の `/home` はログイン後に `/home` へ復帰する。

## 表示

- Collectionは現在名で `display_order`、同値ではIDの順に表示する。
- 最新の保存済み成功Reportがある場合、その行に既存Report詳細へのリンクを置く。
- Reportがない場合は「まだレポートはありません」と表示し、リンクを作らない。
- Collectionが0件なら「表示できるコレクションはありません」と案内する。
- Report詳細では保存時の履歴名を既存どおり表示する。ホームの現在名に置き換えない。
- APIが返す `as_of_date` はサーバー側で一度決定したJST日付である。画面は端末timezoneで再計算せず、その日付を状態件数の見出しに用いる。
- 各Collectionには `queued`（待機中）、`running`（実行中）、`succeeded`（成功）、`failed`（失敗）のJob件数を添える。4件数の合計が0なら状態欄全体を出さず、失敗・未実行・レポートなしを推定しない。
- 件数表示は複数の予定状態を一部だけに絞らず伝えるための補助であり、最新Reportへのリンクと「まだレポートはありません」は件数と独立して維持する。

## 状態・操作

初回表示と再読込時はloadingを表示してGETする。「更新」は一覧全体を先頭から再取得する。取得失敗は個人情報を残さず固定の通信/内部エラーと再試行を出す。401は共有sessionへ委ねてログインへ移り、深いURL復帰を維持する。画面離脱、認証epoch変更、logout、更新開始で表示済みデータを消去し、Abort済み・世代の古い応答を表示へ採用しない。

リンクからReport詳細→ブラウザ再読込→更新→logoutを確認する。更新は全Collectionの最新リンクと当日件数を読み直す。詳細の保存済み本文は既存Report詳細と安全なMarkdown表示を利用し、ホームAPIへ本文を複製しない。JST日付境界と4状態の件数は時計注入・隔離DB fixtureで確認し、route/認証変更/logout後の古い応答を採用しない。

## Collection表示順の変更（Issue #96）

通常表示の「表示順を変更」から編集モードへ入る。現在の行を上へ/下へ移動し、「保存」または「キャンセル」を選ぶ。drag操作は使わない。0件では操作を表示せず、1件では行移動を無効にしても安全に保存/取消できる。ON/OFFにかかわらず本人の現在Collection全件を対象とする。

保存中は二重送信を防ぐ。成功後にhomeと既存 `/collections` の順序を再取得し、通常表示へ戻る。確定409 `order_conflict` は入力順を保持して最新状態の確認・明示的な再編集または取消へ案内する。409 `order_request_conflict` は同じkeyの再利用を止め、現在順を確認してから明示的に新しい操作を始める。どちらも同じkeyの単純再試行を案内しない。通信断・timeout・500・不正な成功応答は結果不明として入力順を保持し、同じ要求key・同じ本文で手動再試行する。状態が確定するまで別内容の保存を防ぐ。

保存成功を確認した後は最新順を再取得する。競合後に最新状態を再取得する場合は、古い下書きと最新のCollection集合を混同して上書きしない。集合が同じで利用者が明示的に再確認した場合だけ新しい期待状態・新keyで再保存可能にする。Collection集合自体が変わった場合は自動mergeせず、古い下書きを保持して明示的な取消/最新順への再読込を求める。

取消・保護route外への移動・再読み込み・認証epoch変更・本人確認/ logout開始で下書き、要求key、API由来の個人データを消し、Abort後または世代の古い応答を画面へ戻さない。候補や順序をlocalStorage/sessionStorageへ保存しない。既存のReport主導線、本日件数、Reportなし表示を保つ。

深URL `/home` の認証復帰、Collection0/1/複数件・同値順、成功後のhome/設定一覧/再読込・logout、競合/結果不明/同一要求再送、取消・入力保持・二重操作、route/epoch遅延破棄、履歴不変と画面幅/キーボード操作を確認する。通信契約は[順序更新API](../API仕様/put-api-collection-order.md)と[ホームAPI](../API仕様/get-api-home.md)を参照する。
