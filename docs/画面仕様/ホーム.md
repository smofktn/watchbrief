# ホーム — Collection別の最新保存済みReport（Issue #92）

## 目的と範囲

認証済みUserが現在のCollectionから最新の保存済み成功Reportを開く最初のホーム経路。業務上の範囲は[プロダクト仕様](../product-definition.md#ホームの最初の経路issue-92)、通信は[GET /api/home](../API仕様/get-api-home.md)に従う。

この画面では現在Collection一覧と最新Reportへのリンクだけを表示する。当日予定状態、Collection並べ替え、次回予定、生成、外部取得、ScheduleからのJob復元は扱わない。

## URLとナビゲーション

保護URLは `/home`。3つの主要ナビの最初のリンクを「ホーム」へ接続する。既存の `/me` は本人情報を確認できる保護URLとして維持し、`/` の遷移先とログイン後の既定先も `/me` のままとする。未認証の `/home` はログイン後に `/home` へ復帰する。

## 表示

- Collectionは現在名で `display_order`、同値ではIDの順に表示する。
- 最新の保存済み成功Reportがある場合、その行に既存Report詳細へのリンクを置く。
- Reportがない場合は「まだレポートはありません」と表示し、リンクを作らない。
- Collectionが0件なら「表示できるコレクションはありません」と案内する。
- Report詳細では保存時の履歴名を既存どおり表示する。ホームの現在名に置き換えない。

## 状態・操作

初回表示と再読込時はloadingを表示してGETする。「更新」は一覧全体を先頭から再取得する。取得失敗は個人情報を残さず固定の通信/内部エラーと再試行を出す。401は共有sessionへ委ねてログインへ移り、深いURL復帰を維持する。画面離脱、認証epoch変更、logout、更新開始で表示済みデータを消去し、Abort済み・世代の古い応答を表示へ採用しない。

リンクからReport詳細→ブラウザ再読込→更新→logoutを確認する。詳細の保存済み本文は既存Report詳細と安全なMarkdown表示を利用し、ホームAPIへ本文を複製しない。
