# WatchBrief ドキュメント

このディレクトリには、WatchBriefの仕様と論理設計を置く。

## 文書の役割

| 文書 | 役割 | 決めること |
|---|---|---|
| [プロダクト仕様](product-definition.md) | 仕様の正本 | 利用者体験、画面、機能、MVP範囲、主要な業務ルール |
| [システム設計](system-design.md) | 論理アーキテクチャ | コンポーネントの責務、生成処理、データとエラーの流れ |
| [ドメインモデル](domain-model.md) | アプリのドメイン設計 | 概念、責務、業務ルール、状態遷移 |
| [DB設計](database-design.md) | 論理スキーマ案 | テーブル、ER図、カラム、外部キー、制約、初期インデックス |
| [技術選定の前提](technical-direction.md) | 選定時の判断材料 | プロジェクト目的、重視する性質、候補、未決定事項 |

仕様と設計が食い違う場合は、プロダクト仕様を優先する。合意した仕様変更は、まずプロダクト仕様へ反映し、影響するシステム設計、ドメインモデル、DB設計も同じ変更で更新する。

## まだ決めないこと

現在は論理設計の段階であり、次の技術選定は未決定である。

- アプリケーションのframeworkとruntime
- DB製品、物理データ型、ORM、migration方式
- Job queueとworkerの実装方式
- AIサービスと呼び出しライブラリ
- デプロイ先とネットワーク構成
- timeout、heartbeat、監視、バックアップの具体値

未決定事項を、実装上の都合だけで仕様として固定しない。候補、理由、影響を整理して合意した後に文書へ反映する。
